# v0.1.3 — owner test feedback (short design)

Date: 2026-11-12. Status: awaiting owner approval. Small change.

## Intent
Fixes from the owner's first real-machine tests of v0.1.2. CPU use was checked and is fine (about 10% while
thumbnails render, about 0% at rest), so it needs no change.

## Changes
1. **Select all.** Ctrl+A, or Cmd+A on macOS, selects every page in the grid. When a text field has focus
   (the Pages field, the password field), the shortcut keeps its normal text behaviour, and while a modal is
   open it does nothing to the grid. This is a new `Workspace::select_all()` with a unit test, wired in
   `ui.rs` next to the Delete key.
2. **Start maximized.** The main window opens maximized (`ViewportBuilder::with_maximized(true)`), with its
   title bar and the taskbar or Dock still visible. It is not fullscreen. 1000×700 stays as the restored
   size. The window size is not remembered between runs (owner was offered this; proposed not to, can be
   added later).
3. **Saving over an open original.** The bottom-bar message is replaced by a centred modal built like the
   existing ones (`confirm_modal`):
   - title "Cannot overwrite the original";
   - body: "<file> is one of the open files. The original is never modified.";
   - buttons "Choose another name" (reopens the save dialog with the same pages, suggesting
     `<stem>_edited.pdf`) and "Cancel".
   - The rule itself does not change: an original is never overwritten. The OS save dialog's own "replace?"
     question cannot be removed, because it happens before the app gets the path.
   - Applies to Save all and Save selection. Split cannot hit it, because its names never match existing
     files.
   - Esc and a click outside count as Cancel, like the other modals.
   - Text goes through i18n (English and Italian). The old `save.blocked_original` key is removed.
4. **Version 0.1.3.**

## Approaches considered (item 3)
- A, chosen by the owner: a modal with "Choose another name", which leads straight back to saving.
- B: an information modal with only "OK". Simpler, but the user must start Save again.
- C: keep the bottom message but make it more visible. Least work, but still easy to miss.

## Non-goals
- Other errors (save failed, corrupt file) stay in the bottom bar for now (proposed; owner may extend later).
- No true fullscreen mode, no remembered window size.

## Testing
Unit test for `select_all`. A kittest test for the new modal's two buttons and Esc. Manual check under Xvfb:
Ctrl+A, the modal, and that "Choose another name" reopens the dialog. The manual checklist gets the three
items.
